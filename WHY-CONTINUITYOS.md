# Why ContinuityOS?

A direct answer to: **Why not just use ChatGPT, Claude, Gemini, or OpenRouter?**

---

## The short answer

Those tools are excellent **models**. ContinuityOS is a **continuity workspace** on **your machine**.

Use any model you want. ContinuityOS is where the thread, backup, recovery, and long-horizon context **stay yours** — recoverable after restarts, upgrades, and mistakes.

---

## Why not ChatGPT?

| ChatGPT | ContinuityOS |
|---------|----------------|
| Hosted history in OpenAI’s ecosystem | SQLite database in **your** user profile |
| Session-oriented UX | Workspace + thread model built for **multi-day** work |
| Recovery = browser hope | **Stream recovery**, snapshots, encrypted backups |
| Cloud-only chat | **Ollama local chat** + Manual Mode for any cloud AI |
| Opaque “memory” features | No surveillance memory dashboard — you export what you choose |

**Use ChatGPT for answers. Use ContinuityOS so the work doesn’t vanish when the tab closes.**

---

## Why not Claude?

Claude excels at reasoning and long context in-session. ContinuityOS does not compete on model quality — it competes on **ownership and recoverability**:

- Paste Claude replies via **Manual Mode** — continuity remains local
- **Encrypted backups** you can audit and move
- **Diagnostics** without sending thread content to a vendor

**Use Claude for thinking. Use ContinuityOS to keep the thread.**

---

## Why not Gemini?

Same pattern: Gemini is a model surface; ContinuityOS is **infrastructure**:

- No Google account required to **start** (Manual Mode)
- Local Ollama path for air-gapped or privacy-sensitive work
- Import preview + rollback — designed for **data you control**

---

## Why not OpenRouter?

OpenRouter aggregates models — great for routing API calls. ContinuityOS is **not** an API router:

- It does not stream every provider inside the app (by design — reduces accidental egress)
- It optimizes **persistence, backup, migration, and recovery**
- Manual Mode + context packs = **you** choose when data leaves the device

**OpenRouter connects models. ContinuityOS protects the work between model calls.**

---

## The continuity difference (core)

### 1. Recoverable continuity

Interrupted generations, app crashes, and restarts are first-class problems — not edge cases.

### 2. Local-first trust

Your database and keys (when used) stay on device. Diagnostics are local-only.

### 3. Honest AI boundaries

- **In-app chat:** Ollama (local)
- **Everything else:** Manual Mode — explicit copy/paste

No pretense that “the app” is simultaneously every cloud provider.

### 4. Backup as a feature, not an afterthought

Encrypted export, import preview, rollback — continuity you can **hold in a file**.

### 5. Calm product ethics

No agents running while you sleep. No collaboration complexity. No marketplace noise.

---

## When ContinuityOS is the wrong tool

- You want a single hosted chat with zero local files → use ChatGPT/Claude/Gemini
- You need real-time multi-user editing → ContinuityOS v1 is not built for that
- You want autonomous agents → not in scope

---

## When ContinuityOS is the right tool

- You run **local models** and want persistence better than a terminal log
- You use **multiple AIs** but one **project thread** should survive
- You’ve **lost work** to tab closes, crashes, or provider UI resets
- You care about **backup, migration, and recovery** as much as the next prompt

---

## One-line positioning

> **ChatGPT answers. ContinuityOS remembers — on your machine, under your control.**
